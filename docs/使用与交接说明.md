# YouTube 转录工具：完整使用与交接说明

维护日期：2026-11-01。本文以仓库代码为准，记录当前功能，不代表每次云端环境都已配置好。
修改程序行为时应同步修改本文；只有文档更新时不要顺手调整推理参数、依赖或本机安装。

## 1. 先记住这一条主流程

```text
Windows 本地下载 YouTube 音频
    → 把音频交给连接本仓库的 Codex Cloud 对话
    → Codex 云端 CPU 逐个转录，每完成一个就保存到 GitHub
    → 把 GitHub TXT 链接或下载的 TXT 交给 ChatGPT 解读
```

这条路线中，本地电脑负责下载，Codex 云端负责计算，GitHub 负责保存，ChatGPT 负责分析。
**默认不启动 GitHub Actions，不自动上传 Google Drive，也不自动保存到 ChatGPT Library。**
本地下载完成后，真正的云端转录不依赖本地电脑继续开机；但它仍受当前云端任务的运行期限限制，不是永久后台服务。

- [工具源码、文档（main）](https://github.com/wangshen2014-collab/youtube-transcriber-cloud)
- [已保存结果索引（transcripts）](https://github.com/wangshen2014-collab/youtube-transcriber-cloud/tree/transcripts)
- [给执行代理的规则](../AGENTS.md)

## 2. 日常使用：四步操作

### 第一步：本地下载音频

1. 启动已安装的「YouTube 视频转文字」：`C:\Users\rsun2\YouTubeTranscriber\YouTube Transcriber.bat`。
   如果桌面快捷方式失效，可直接运行这个启动文件；本文没有重新创建或验证快捷方式。
2. 右上角切换到「仅下载音频」，粘贴 YouTube 链接。
3. 一般选择完整视频。只需部分内容时，选择自定义时间段，填写开始和结束时间。
4. 输出目录使用 `C:\Youtube音频输出`，或自行选择目录。
5. 如果上传界面有单文件大小限制，勾选「自动拆分音频（仅下载，每份不超过 30 MB）」。
   **默认不勾选**。勾选后，超过 30,000,000 字节的导出会拆成最多 30 分钟的独立 M4A，仍超限则继续拆小。
6. 点击「下载音频」。需要多个视频时，可继续添加任务，按队列顺序执行；留意日志中的成功或失败状态。
7. 在输出目录找到以视频标题命名的音频，上传时保持文件名和分段顺序。

完整音频通常保留源音轨格式，如 WEBM/M4A；部分音频导出为 AAC/M4A。
例如 `视频标题 [00-00-30 至 00-03-30].m4a`；分段会包含「第001段」及原始时间范围。
文件名中的 Windows 非法字符会处理，中文标题可以保留。已有文件不会被直接覆盖。
即使只导出一段，程序仍可能先缓存完整源音频；不保证只下载该时间段。
仅下载不加载 Whisper，也不会自动提交云端任务。

### 第二步：交给 Codex Cloud 转录

选择连接本仓库 `main` 的 **云端环境**，上传本次需要的音频附件。
确认没有误用本地执行环境，也不要只上传文件后就等待自动运行：还需要发出指令。

日常最短指令：

> 全部转录，按仓库 AGENTS.md 的默认流程，在当前 Codex 云端执行，每完成一个就保存到 GitHub，返回结果链接。不要启动 GitHub Actions。

只转一段：

> 只转录本次附件的 02:15–08:40，其他按默认流程，完成后保存到 GitHub。

时间范围相对于**本次上传的音频文件**。如果本地已经剪过一段，再指定范围会再次裁剪。
批量命令中的 `--start/--end` 会应用于所有输入；不同文件要转不同范围时须分别指定任务。

多个附件串行执行；一个失败不会阻止后续文件。不要同时启动多个相同批次。
不需要把音频转成 Base64、把二进制内容贴进对话，或让模型阅读整个音频文件。
音频由解码器和 Whisper 处理，不是通过把全部二进制塞进语言模型上下文来转录。
这不构成对任何账户额度、运行时长或费用的保证。

### 第三步：确认结果已保存到 GitHub

每个成功文件会发布三种结果：

| 文件 | 用途 |
| --- | --- |
| TXT | 阅读、交给 ChatGPT 总结分析 |
| SRT | 带时间戳字幕，回看原视频定位 |
| JSON | 检测语言、配置、耗时及运行报告 |

打开 [结果索引](https://github.com/wangshen2014-collab/youtube-transcriber-cloud/tree/transcripts)，
进入对应文件的结果页，使用 TXT/SRT/JSON 或「直接下载」链接。
让 Codex 返回每个成功项目的结果页和 TXT 直链，并列出失败或待发布项目。
只看到云端 `/workspace/...` 路径，并不等于已经有可下载或持久保存的结果。

同一音频内容和相同参数已保存时，脚本会跳过重复计算；同名但不同内容不会被当成同一个任务。
相同内容改名也可能返回原来保存的结果名称，而不是创建另一份。

本地工具生成的连续分段，只有名称、编号、原始时间范围和实际时长符合规则时，才额外生成
「已上传分段合并」结果，并给合并 SRT 加回原始时间偏移。合并版发布成功后删除单段结果，
仅保留合并版和去重记录；合并失败保留分段。
这个名称只表示合并了已上传分段，**不保证上传了整个视频**。不要手动去掉分段编号和时间范围。

### 第四步：交给 ChatGPT 解读

优先提供对应结果的 **TXT 直接链接**，需要定位时再提供 SRT；不要只给仓库首页或 ZIP。

> 请读取这个转录 TXT：〔TXT 直接链接〕。总结主要观点、依据、风险和前后矛盾；把讲者观点与事实核查分开。无法访问链接时请直接告诉我，不要猜测原文。

具体对话的浏览/文件工具可能无法读取链接。遇到访问限制，就自己下载 TXT 并作为附件上传，
不要把「公开链接」理解为任何 ChatGPT 对话都一定能直接访问。
转录可能错听股票代码、数字、专有名词；关键结论应回看原视频核实。
目前只有声音转文字，**不会读取图表、PPT 或自动截图**，也不会自动把结果推送到另一个 ChatGPT 对话。

## 3. 第一次配置云端环境

以下供新对话或维护者执行，不需要每次手动重复操作。

1. 使用包含当前代码的仓库 `main`，先读 `AGENTS.md` 和本文。
2. 在 Linux 仓库根目录，环境尚不可用时运行 `bash scripts/setup.sh`；可用时复用现有环境。
   脚本建立 `.venv`、安装依赖、检查导入并运行测试；模型在首次转录时下载。
3. 确认任务运行阶段可以访问模型下载主机和 GitHub API。
   已遇到过的主机包括 `huggingface.co`、`us.aws.cdn.hf.co`、`api.github.com`；下载重定向还可能涉及其他主机。
   TXT 直链使用 `raw.githubusercontent.com`。按实际错误检查网络策略，不关闭 TLS、不绕过平台代理。
4. 提供仅限本仓库的 GitHub **Contents 读写**授权，供脚本发布 `transcripts` 分支。
   脚本支持 `GH_TOKEN` / `GITHUB_TOKEN` 或可用的已授权 Git 凭据。
   只放在环境安全配置中，不贴进聊天、命令参数或仓库。连接仓库不保证脚本已有 API 写权限。
   安装阶段可用的密钥，也不保证在任务执行阶段自动可用。
5. 批量脚本会先验证结果存储写权限，再开始长时间转录；授权失败应先解决，不要白算几个小时。

默认命令：

```bash
# 显式列出本次附件，顺序执行；路径换成实际附件路径
.venv/bin/python batch_transcribe.py '/path/视频一.m4a' '/path/视频二.webm'

# 只有该目录明确专属于本批附件时，才使用目录扫描
.venv/bin/python batch_transcribe.py --input-dir incoming/本批音频

# 每个输入都只转录相同范围
.venv/bin/python batch_transcribe.py '/path/音频.m4a' --start 02:15 --end 08:40
```

也可提供 GitHub Release 音频附件作为传输入口：明确指定附件后，由 Codex 普通二进制下载到
`incoming/`，再运行同一个批量脚本。**提供 Release 链接不代表要求改用 GitHub Actions。**
手动上传公开 Release 的源音频也是公开的，且不由默认结果流程自动清理。

| 执行规则与入口文档 | `AGENTS.md`、`README.md`、本文 | 新对话接手与日常说明 |

`desktop/` 是已安装应用的源码副本，GitHub 更新不等于自动更新 Windows 安装。
云端任务不要改本机安装；本机发布时需另行同步相关文件并验证，先确认用户没有任务在运行。
安装目录中的 `README_中文.md` 还有旧版本机说明/性能测试资料，本文不会覆盖它。

默认云端参数：multilingual **medium**、`device="cpu"`、`compute_type="int8"`、6 线程、
`beam_size=3`、`condition_on_previous_text=True`、VAD 关闭、自动检测语言、`task="transcribe"`。
中文显式选择用 `zh`，英文用 `en`；不是翻译模式，TXT 保留原语言。
本地模型映射是 small / medium / large-v3，多语言模型，不是 small.en / medium.en。
不要因为维护文档、修下载器或更换存储而顺手改变这些参数。

云端依赖以 `requirements.txt` 为准：faster-whisper 1.2.1、CTranslate2 4.4.0、PyAV 16.0.1、setuptools<81。
本机安装版本可能不同；不要用云端依赖文件不加检查地覆盖本机虚拟环境。
本地下载组件通过应用自己的「更新下载组件」更新 `yt-dlp[default]`，包括匹配的 EJS 组件；
优先用应用自己的 Node，不依赖 Codex 打开着。

## 5. 缓存、保留期限与公开范围

| 数据 | 位置与保留方式 |
| --- | --- |
| 本地源音频缓存 | `%LOCALAPPDATA%\YouTubeTranscriber\audio-cache`，按视频 ID 缓存；48小时/7天/30天/手动清理，按最后使用时间。默认7天，实际以GUI选择为准 |
| 本地导出音频 | 通常在 `C:\Youtube音频输出`；已登记、未被修改/替换的导出音频，导出后7天清理。启动及每小时检查，不是精确到秒 |
| 本地导出登记 | `%LOCALAPPDATA%\YouTubeTranscriber\audio-exports.json`；不是模型目录 |
| 真正临时文件 | `%LOCALAPPDATA%\YouTubeTranscriber\temp`；正常成功/失败在finally清理，启动也清理过旧遗留 |
| 本地模型/队列/检查点 | 同一 LOCALAPPDATA 根目录下的 `models`、`task-queue.json`、`checkpoints` |
| 下载的视频、TXT/SRT | 最终输出目录；不属于导出音频7天清理 |
| 云端工作文件 | `outputs/cloud-batch/`、`state/cloud-batch/`、`models/`；任务本地目录，不保证跨新环境保留 |
| GitHub 默认结果 | `transcripts` 分支：`jobs/<任务键>/`、索引、`progress/<任务键>.json`；**公开、不自动过期** |
| 旧版 Actions 结果 | Artifact，配置保留60天；不是默认 `transcripts` 分支的保存规则 |

GitHub 默认结果分支只允许 TXT/SRT/JSON 及文字检查点，不上传源音频、模型、Cookie 或令牌。
检查点也包含转录文字，是公开内容。删除当前文件不等于抹去 Git 历史。
源音频不提交到代码分支，不代表其转录文字不敏感；会员、隐私、未公开内容在公开发布前必须确认权利和授权。
需要私有保存时，先调整目标和授权，不要直接沿用当前公开分支。
「清空音频缓存」要确认后永久删除缓存，不进回收站，不删除 Whisper 模型和 TXT/SRT；
缓存和输出目录内的导出副本不是同一份文件，清缓存不等于删除所有导出音频。

## 6. 排队、暂停、续做与失败处理

### 本地程序

- 单个工作队列串行执行；等待数不包括正在执行的那一个，等待0不一定是没排队，也可能前项已失败。
- 「暂停当前任务」在安全点生效，不保证即时暂停；下载或模型加载中可能需要先等该阶段返回。
- 「继续未完成任务」使用已保存的队列/检查点。没有检查点的阶段可能重新执行。
- 任务期间请求 Windows 不自动休眠，但**不能阻止手动关机、重启、强制断电或所有合盖策略**。
  离开前应先暂停并确认状态，不要把防休眠当成关机保护。

### Codex 云端批量任务

- 在当前环境用相同音频及参数重新运行：已完成但发布失败的结果优先重新发布，不重新推理。
- 已经发布的内容与参数相同：跨任务去重，返回既有结果。
- 每10分钟及暂停/失败退出时尝试同步文字检查点。新任务要续做，仍需重新提供**完全相同的音频字节**。
- 音频重新编码或内容变化会产生新任务。仅改名不改变内容身份。
- SIGINT/SIGTERM、或指定 `--pause-file` 后创建该文件，可请求安全暂停；退出码75表示暂停。
  使用暂停文件时恢复前删除自己创建的暂停文件。
- 不保证强杀、任务超时、环境销毁后零损失；最近未同步的一段可能需要重算，恢复措辞也可能不同。
- 不把进程偷偷丢到后台就宣称完成；应在当前任务支持的终端执行机制内跟进到结束。

| 现象 | 下一步 |
| --- | --- |
| Codex 云端 YouTube CONNECT 403 | 走本地下载再上传的主流程；不要反复改推理参数或声称转录已成功 |
| 模型下载失败 | 检查实际重定向主机、任务生效网络策略及模型缓存，不关闭TLS校验 |
| GitHub 401/403 或 API CONNECT 403 | 分别检查凭据权限/任务阶段可用性与网络；公开仓库也不是匿名可写 |
| `publish_pending` | 保留本地结果，修好授权/网络后重跑原命令，避免重新计算 |
| `failed` / `completed_with_errors` | 查看 `state/cloud-batch/batch-status.json` 和对应 `worker.log`，逐项报告，不能把全批说成成功 |
| 只得到 `/workspace/...` 链接 | 确认实际发布完成并返回 GitHub 结果链接；不要将任务内路径冒充下载链接 |
| 分段未合并 | 检查编号、标题、范围是否连续及实际时长是否匹配；单段结果仍可使用，不猜测拼接 |

## 7. 本地视频、会员与尚未实现的功能

本地还支持「下载视频（含声音）」：720p/1080p上限，优先兼容H264，合并声音与画面；
最终可能为MP4或MKV，按实际可用格式决定。目前视频只支持完整下载，不支持选时段导出视频。

普通公开视频默认不读登录信息。会员视频只能在用户明确授权后使用指定浏览器或本地Cookie文件，
账号必须有对应观看权限；不绕过DRM、系统加密或欠缺的会员权限，也不保证下载一定成功。
Chrome数据库可能锁定，Cookie也可能过期；不要擅自关浏览器或改读其他账号。
Cookie源文件不修改，临时副本清理；绝不上传聊天、Codex Cloud或GitHub。

下列是想法或外部环节，**不是已经完成的产品功能**：

- Google Drive 自动保存、ChatGPT Library 自动保存。
- 无需发指令、上传后自动触发的永久队列服务。
- 自动把结果发到另一个 ChatGPT 对话并完成分析。
- 视频PPT/图表的语义截图、等待逐条内容展示完整后截图、截图与字幕联合分析。
  当前仅讨论过方案，尚未实现；声音转录不会包含只出现在画面上的数字和图表。

## 8. 给新对话的交接指令

只想日常转录，用第2节短指令即可。维护或接手开发时，可复制下面这一段：

> 请先阅读仓库 AGENTS.md、docs/使用与交接说明.md 和 README.md，并检查当前代码及 git status，不要只依赖旧聊天。
> 我的默认流程是：Windows下载音频 → 当前Codex Cloud执行批量转录 → 每完成一个发布到GitHub transcripts分支 → 我交给ChatGPT分析。
> 默认入口是batch_transcribe.py，不是cloud_job.py，不要擅自启动GitHub Actions或本地电脑计算。
> 保留medium、CPU int8、6线程、beam3、condition_on_previous_text=True、VAD关闭和原语言转录。
> 只处理本次明确提供的文件，先验证GitHub写权限，逐个返回可用结果链接；续做沿用原参数与相同音频。
> 修改前区分源码仓库和本机安装，确认是否有任务在运行；不上传Cookie、源音频、模型或密钥，不公开未获授权内容。
> 本轮先概述当前状态、拟修改文件和验证办法，再按我的具体请求继续。功能有变化时同步更新本文。

维护验收：

1. 先读代码，区分「已实现」「过去实测」「本次实际验证」，不把旧报告当成本次测试。
2. 运行 `.venv/bin/python -m unittest discover -s tests -v`，记录实际结果；仅文档修改可做对应链接/命令核对。
3. 改转录流程时需实际生成并抽查TXT/SRT及报告；改发布流程时需验证实际结果链接，不只看退出码。
4. 只提交预期源码/文档；检查不含音频、运行状态、Cookie、令牌或会员内容，提交到main。
5. 结果发布由脚本写transcripts；不要用源码提交覆盖该分支。禁止force-push、清空历史或破坏用户现有修改。

## 9. 如何跟踪文档版本

本文与源码一起放在 `main`，通过Git提交记录追踪；转录结果独立放在 `transcripts`。
在GitHub打开本文后，使用 **History** 查看修订；需要引用固定版本时使用对应提交的文件链接。
后续每次功能变更同时更新相关章节，提交信息说明改动；本地路径和依赖版本可能变化，接手时以实际环境复核。

## 10. 转录资料库与目录整理

## 查找已经转录好的内容

**[打开转录资料库（按节目／视频分类）](https://github.com/wangshen2014-collab/youtube-transcriber-cloud/tree/transcripts)**

日常找字幕只需收藏这个入口，无需切换分支或记住任务编号。资料库把合并版、单段、测试样例和批次归档分开，并提供 TXT/SRT/JSON 链接。

| 位置 | 保存什么 |
| --- | --- |
| `main` 分支 | 工具源码、使用说明，不是字幕文件夹 |
| `transcripts` → `catalog/` | 按节目查找的目录，每次标准发布自动重建 |
| `transcripts` → `jobs/` | 实际结果；任务编号是稳定存储标识，保留原路径 |
| `transcripts` → `batches/`、`collections/` | 旧批次记录及合并版副本，不保存 ZIP |
| `transcripts` → `progress/` | 未完成任务的文字检查点 |
| [旧版 Actions 归档](https://github.com/wangshen2014-collab/youtube-transcriber-cloud/blob/transcripts/LEGACY.md) | 有到期日的旧下载包；失败包可能仅有诊断信息 |
| [Releases](https://github.com/wangshen2014-collab/youtube-transcriber-cloud/releases) | 上传的原始音频，和转录文字分别存放 |

整理保留最终结果和 Git 历史；合并成功的单段文件及 ZIP 会删除，相关目录链接指向合并版。合并版只说明合并了已有内容，不证明覆盖原视频全片。现有目录按文件名归组，不代表重新核验转录准确性。

标准发布由 `github_results.py` 在同一个原子提交中更新结果及目录，分类逻辑在 `result_catalog.py`。人工发布自定义结果后也应重建目录；最终结果保留 `jobs/` 的任务键、manifest 和原文件路径；已清理分段通过 `retired-parts.json` 兼容去重。树列表截断时停止发布，不能静默生成缺项目录。旧版 Actions 清单是 2026-11-01 盘点快照，实际可用性和到期状态以 GitHub 为准。

### 结果保留规则

不再生成或保存 ZIP。保留 TXT、SRT 和 JSON；连续分段核验并成功发布合并版后，删除单段结果文件，仅保留最终合并版及少量去重记录。合并失败时保留分段，重试无需重新转录。
