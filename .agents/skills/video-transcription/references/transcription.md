# 转录执行与复核

本参考供完整转录使用。总结需要内部识别时，只应用环境、输入、配置、预算与运行部分；TXT/SRT交付、发布及文字检查点上传要求不自动适用。

## 2. 用户偏好与保存目标

- 计算在当前 Codex Cloud 内完成，不切到用户本机，不默认启动 GitHub Actions。
- 首要交付是 TXT 直接下载链接。通常同时保留 SRT 供定位、JSON 供记录配置与复核过程。
- 不生成、保存或上传 ZIP。GitHub 只保存最终文字结果与必要的文字检查点，不保存原始音视频、模型或凭据。
- 默认 GitHub 目标：`wangshen2014-collab/youtube-transcriber-cloud`，分支 `transcripts`。用户指定其他位置时采用本次指定。
- 是否上传遵循本次会话的明确授权；已有授权不反复询问。新聊天没有上传授权时，先按仅交付文件处理，不自动公开结果。
- 用户明确要求上传时，先验证目标与写入权限，再进行长时间推理。缺少连接或写权限时说明具体缺项；不索要聊天中粘贴的令牌。
- 视野环球财经：归入 `collections/视野环球财经`，保留现有目录、旧结果和元数据。其他频道不要误放进此栏目。
- 同一视频连续分段只保留最终合并成果；不同视频分别保存，不因题材类似而混成一份。

### 来源署名与角色

- 区分上传频道、作者/主持人、受访者和观点归属。频道或文件名含有人名，不自动证明谁在说话或谁持有观点。
- 用户明确提供角色时，保留其原始限定；当前仓库支持对应参数时，使用 `--channel`、`--author`、`--interviewee`、`--opinion-owner` 传递。本地入口没有这些参数时不能编造支持，需先核对当前代码。
- 用户提供的归属元数据不是独立核实的事实，也不能用作语音识别提示或强制替换不清楚的人名。不同角色的视频分别调用，不能给同批所有输入套用一个人名。
- 保留当前程序生成的TXT来源块和首个SRT元数据cue，明确它们是元数据而非口述；一致性校验按程序格式处理，不把来源块伪造成说话内容或新造时间。

## 3. 环境与输入检查

1. 若有 `cloud_environment.environment_status`，调用并确认机器身份、当前就绪状态与云端提供方。环境启动中则使用等待工具；不可用时不冒充已开始计算。
2. 阅读当前工作区适用的 `AGENTS.md`。原工具仓库还需阅读 `docs/使用与交接说明.md`；复用可用的虚拟环境、模型缓存和发布功能，不为一次转录修改产品代码。
3. 未指定精度时使用普通档 medium/beam3；明确“中高”使用 large-v3/beam3，“高精度”使用 large-v3/beam5。题材不决定精度。需要偏离适用默认时先简短说明实际设置。
4. 检查 CPU 配额、可用内存与模型，不把宿主机显示的 CPU 数当作可使用的核数；不假设有 GPU。
5. 附件传入后确认非空、可解码、实际时长、声道和 SHA-256。文件名相同不代表音频内容相同。
6. 附件传输限制以当前工具为准。已遇到 `download_file` 的 32 MiB 限制；超限时报告实际错误，检查是否已有合法的工作区副本。没有可用副本则请用户提供较小音频或每份不超过约30 MB的连续分段，不重复尝试同一个硬限制，不把音频转成 Base64 塞入上下文。
7. 仅有 YouTube 链接时，按当前工具与仓库允许的路径尝试获取。若用户已禁止重试 `yt-dlp`，不得重试。不得绕过代理、读取未授权 Cookie 或关闭 TLS。

### 下载失败必须区分

| 实际证据 | 可作出的结论 |
| --- | --- |
| 建立代理隧道时 `CONNECT ... 403` / `Tunnel connection failed: 403` | 代理或隧道阶段被拒绝；不能称为 YouTube 返回403 |
| 隧道已建立，收到目标站点的 HTTP403 或播放器拒绝信息 | 按返回内容报告目标服务拒绝；不能猜测一定是地区、登录或机器人检测 |
| 只有笼统403，没有请求阶段、响应或诊断 | 原因无法确认；明确说明证据不足 |

如需诊断生效策略，可读取状态工具和存在的 `/etc/codex/network-policy.json`，只输出相关主机的策略状态，不输出密钥。只有证据齐全时，才区分“配置未生效”“生效规则未放行”“规则允许但代理仍拒绝”；配置允许不等于连接成功。

失败时返回完整相关错误链，遮蔽令牌、Cookie和签名等敏感值。输入未成功取得或推理未完成，不能声称转录成功。

## 4. 固定精度档，避免反复整片重跑

| 用户要求 | 默认主模型 | beam size | 复核方式 |
| --- | --- | --- | --- |
| 普通／普通精度；只说转录或财经转录 | multilingual medium | 3 | 关键术语和异常段 |
| 中高／中高精度 | multilingual large-v3 | 3 | 关键数字、金融概念、漏段与疑难片段 |
| 高／高精度 | multilingual large-v3 | 5 | 更充分的关键片段与异常复核 |

- 通用设置：`task=transcribe`、自动语言、CPU `int8`、VAD关闭、主转录 `condition_on_previous_text=True`。用户另有指定或适用规则另有要求时遵循并记录。
- `medium/beam5` 可作为经说明的资源折中方案，不能宣称它等同于 `large-v3/beam3`。更大模型也不保证每句更准确。
- 线程数按实际配额安排并记录；普通仓库默认线程数与实际使用值不同时说明资源原因。四核单任务通常4线程；两份从一开始并行通常各2线程。
- 尽早检查完整任务已生成的首1—2分钟，不默认另跑一个参数不同的 `--end` 样本后假装能直接续成整片。
- 初稿确有系统性错识时，允许一次有理由的模型调整；保留旧任务为未完成或被替代状态，另立匹配配置的任务。不要无止境切模型、悄悄改参数，或把不匹配的断点强行拼接。
- 授权使用仓库批量发布入口时，`batch_transcribe.py --quality` 支持 `standard`、`medium-high`、`high`。线程默认固定为 6，也可用 `--threads` 显式指定。续做时使用相同的实际参数。其他入口须核对实际使用的模型与 beam。本技能的档位是配置约定，不承诺准确率。
- 完整或高精度转录以原音频为准。同一视频的频道方原语言字幕可以辅助定位和术语复核，自动字幕须标明来源。字幕和音频有出入时回听，无法确认就保留标注。

单项 CLI 参考命令，路径与线程值应换成本次实际值：

```bash
.venv/bin/python transcribe_cli.py \
  --audio-file '/实际路径/音频.webm' \
  --model large-v3 --beam-size 3 --threads 4 \
  --language auto \
  --state-dir 'state/本任务独立目录' \
  --output-dir 'outputs/本任务独立目录'
```

此命令只负责推理；是否已上传必须另行验证。不要在其他聊天中假定旧任务目录、模型文件或连接凭据仍然存在。

### 额度与复核预算

- 先完成一个选定主模型的整片任务；不要默认用多个模型把整片各跑一遍。观察首段后若需升级，遵循上面“一次有理由调整”的规则。
- CPU推理、模型下载和Codex对话中的阅读、分析、工具调用是不同的资源消耗；不能承诺本地Whisper计算就不消耗Codex额度，也不能假装能读到账号剩余额度。
- 未另指定预算时，复核优先级为方向/条件、关键数字、缺口、重要术语，最后才是口头禅和推广段。普通/中高/高档可分别以源时长约5%/10%/20%作为初始复核音频预算；这不是必须跑满的指标，也不是质量保证。
- 短视频优先选最关键的1—3段；单个疑点通常最多两次独立机器解码（可包含一次补充模型）。预算将尽或两次结果不再改善，保留时间戳和待核标记，不无限重跑。若发现大范围识别失败，应明确报告质量未达标，不用一稿大量待核宣称精准完成。
- 预算外的重要疑点未解决时，先交付完整转录和待核清单，说明限制；只有用户要求继续追加复核，才继续消耗。不得为了达成某个复核百分比重复计算清楚的内容。
- 每个文件记录主模型启动次数、复核片段数和累计复核秒数。读取一次全稿后优先检查短上下文与差异，避免在工具输出里反复打印整片或大段重复文本。安装或审核本Skill时，不重新转录历史音频作为验证。

## 5. 并行、续做与运行纪律

- 用户要求并行且资源允许时，真正同时运行不同输入的计算；不要把排队描述为并行。未要求时按适用仓库的默认队列执行。
- 每个输入使用独立状态、日志、输出和任务标识，避免检查点相互覆盖。保持模型内存加音频解码的总峰值低于实际内存额度。
- 初始并行规划尽量让总计算线程不超过配额。已运行的任务保留原参数和断点；新任务若只能共享配额，应说明会共享 CPU，并行不保证提速。
- 不要把4线程的 CTranslate2 任务硬绑到2颗 CPU 来假装它是2线程：可能出现线程争抢或自旋，严重拖慢任务。CPU affinity 与模型线程数不是一回事。
- 已完成一份就先校对、交付或发布一份，同时继续其他任务；最终答复仍列出所有结果及未完成项。
- 使用支持轮询的前台长会话跟进；保持可接收用户新指令。不偷偷启动无人跟进的后台守护进程，不承诺任务结束后永久运行。
- 约每10分钟保存适用的文字检查点；只有上传授权覆盖文字检查点时才同步到 GitHub。暂停、失败与完成分别记录。
- 续做校验同一音频字节与同一配置；完成后发布失败应重发已有结果，不能无理由重跑推理。不能保证强杀或环境销毁后零损失。
- 简短报告有意义的阶段、进度和阻塞，不反复输出模型日志、整份转录或推测的完成时间。

## 6. 内容校对：忠实原话，不用常识补答案

以下金融清单仅用于财经内容，普通精度也保留必要的关键疑点检查；其他领域核对相应术语、人名、事实条件和操作步骤，不默认提高精度。所有题材均保留否定、限定、自我修正和重要数字。

### 优先复核

- 加息／降息，买入／卖出，加仓／减仓，做多／做空；已发生、计划、可能与条件句。
- 正负号、百分比和百分点，小数、数量级、币种与单位；营收、利润、现金流、承诺与已发生债务之间的区别。
- 股票、ETF和指数的区别，尤其 SPY 的价格与标普指数点数、QQQ 的价格与纳指点位，不擅自按比例换算。
- 股价区间上下限、开盘／收盘／盘中、止跌形态、仓位百分比、剩余仓位和止损条件。
- 节目日期、自然年与财年、季度、期限，以及“未来”“截至某日”等时间基准。
- 关键概念与缩写：EPS、PE/P/E、PS/P/S、FCF/free cash flow、CapEx、CPI/core CPI、CTA、Gamma、HBM、GPU、CoWoS、ETF、CME、SEC、CFTC等。

这些是核对清单，不是强制替换词典。不得因存在熟悉术语，就把不清楚的原音强填成它。

### 允许的文字校对

- 在本段语境和原音支持下规范明确的实体名、同音错字、英文大小写与单位，例如“英美达”对应英伟达、“编辑成本”对应边际成本。
- 对口述的相邻数字加分隔，如明确说“7200、7300”却连成“72007300”；每次数值相关修改记录原文和依据。
- 保留讲者的观点、自我修正、真实重复和口误。不要把校对变成润色、概括或代写逻辑。
- 不做跨视频自动映射。某期代码听成 SRG，不能因为另一视频清楚说 ISRG 就给本期加字母；不能把“美元”凭叙事合理性改成“欧元”。

### 独立机器复核

1. 以原始音频截取带少量前后文的片段，记录绝对起止时间和疑点。
2. 可用 `large-v3/beam5`、VAD关闭、`condition_on_previous_text=False` 独立解码；必要时用另一模型或不同切段作补充比较。
3. 提示词可给一般主题或确定的词汇背景，不给待确认的数字、日期、结论或“应该听到的整句”。
4. 多模型一致只是支持证据，不等于原音已确认。反复重跑不是人工听写；如果没有实际人工听辨能力，不得声称“人工听写”“人工逐字核实”或“已经听懂”。
5. 仍无法确认就标 `[数值听辨待核]`、`[股票代码听辨待核]`、`[术语听辨待核]` 等；SRT和JSON保留定位时间。
6. 复核到证据不再改善就停止反复解码。不要用会计加总、估值计算、当前行情、网页报道或多数投票猜回原文。

例如，数段先后出现909亿和9009亿，不能靠加总补零；某段551亿不能因公式算出550亿就改写。不能确认的一处应标待核，不能顺手“统一”其他清楚的口述。

### 漏段、重复与修订记录

- 检查异常时间缺口、超长无字区间、窗口尾部重复与不合理短句。时间缺口不自动等于漏音，也可能是静音，必须回到对应音频片段核实。
- 完整一句挤在0.02秒或0.26秒并重复前句是异常线索；仅凭时长不删除，需结合前后段与独立解码。正常强调、停顿和重说不能机械去重。
- 有声内容确被主解码漏掉，独立解码补回并保留原始时间；不能只让TXT看起来连贯而漏修SRT。
- 对替换记录 `start/end`、`before`、`after`、依据或复核片段。保留原始输出和复核证据，最终TXT、SRT应用同一组修订。
- 不设置“必须复核一半音频”的机械指标；把计算用在会影响理解的疑点与关键段落，不把整片反复重跑当作质量保证。

## 7. 日期、分类与连续分段

- 用户明确指定的归档日期优先，其次采用可靠的片头口播或来源元数据。上传日期、转录日期、星期几和文件名猜测都不能单独证明节目日期。
- 归档日期与口播冲突时分别记录；不默默改掉原文年份。日期无法确认时使用标题和“日期未核”，把本次转录日期单独写进JSON。
- 其他频道各自归档；用户明确要求并入某合集时，读取现有索引后追加，不重建成丢失旧条目的新集合。
- 合并分段前核对共同视频身份、编号、文件名原始时间范围、实际时长和是否有重叠／缺段。仅文件名相似不够。
- 合并时为每段SRT加回原始时间偏移；校验时间、段序、重复边界和覆盖范围。“已上传分段合并”不自动代表已覆盖原视频全片。
- 合并成果验证并持久保存后，再清理单段结果和文字检查点，保留最小去重记录。合并失败保留单段，不丢数据。

## 8. 发布与完成门槛

发布前确认：

- 实际推理状态为完成，音频身份匹配，选择范围正确；部分输出、暂停或仅下载成功都不是完成。
- TXT、SRT和JSON真实存在，TXT内容与SRT文本一致，时间合法、有序且不超范围，缺口已核实。
- JSON记录真实模型、beam、线程、语言、执行后端、时长、阶段耗时、近似内存、复核与修订、日期依据和存疑项；不把机器复核写成人工核实。

GitHub发布：

- 优先使用可用的 GitHub 连接工具或仓库发布功能。读取新鲜分支头和完整文件树；树截断时停止，不生成缺项目录。
- 只写本次结果、必要索引和授权的合集内容。保留旧结果、链接、集合索引及未知元数据，不覆盖用户或其他任务的新提交。
- 通过树、提交和分支引用更新完成原子写入；使用预期分支头校验，禁止强推。提交加 `[skip ci]`，不触发或另行启动 Actions。
- 更新 `jobs/`、结果目录和需要的合集索引；成功后清理相应文字检查点。
- 从真实下载地址读回最终内容，核对文本或哈希。API返回成功、退出码0、链接看起来正确，都不能代替下载验证。
- 上传失败时明确标为“已转录／待上传”，保留文件和断点，提供可用的本次文件下载，不虚构GitHub链接。

最终简短交付：每份视频一条 TXT 下载链接，必要时附合集入口，并说明重要存疑或未完成项。只有本次本地文件就给真实文件链接，不把工作区路径冒充永久GitHub下载地址。
